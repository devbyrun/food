================================================================================
                      การออกแบบฐานข้อมูล (Database Schema Design)
                   ระบบสั่งอาหารตามโต๊ะผ่าน QR Code (Multi-Store)
================================================================================

1. ภาพรวมระบบฐานข้อมูล (Database Overview)
--------------------------------------------------------------------------------
- รูปแบบฐานข้อมูล: Relational Database (แนะนำ PostgreSQL หรือ MySQL 8.0+)
- รูปแบบสถาปัตยกรรม: Multi-Tenant แบบ Shared Database, Separated by `store_id`
  (รองรับการใช้งานหลายร้านค้าในระบบเดียวกันอย่างปลอดภัยและเป็นสัดส่วน)
- การเข้ารหัสตัวอักษร: `utf8mb4` / `utf8mb4_unicode_ci` (รองรับภาษาไทยและ Emoji เต็มรูปแบบ)
- มาตรฐานเวลา: `TIMESTAMP WITH TIME ZONE` (UTC)


2. รายการตารางทั้งหมด (Tables Summary)
--------------------------------------------------------------------------------
กลุ่มที่ 1: ระบบผู้ใช้และร้านค้า (Users & Stores)
  1.1 users                  - ข้อมูลผู้ใช้งานระบบทั้งหมด (Admin, Manager, Staff)
  1.2 stores                 - ข้อมูลร้านค้า
  1.3 store_users            - ความสัมพันธ์และสิทธิ์ของผู้ใช้ในแต่ละร้าน

กลุ่มที่ 2: ระบบจัดการโต๊ะ (Tables & QR Code)
  2.1 table_zones            - โซนของโต๊ะอาหาร (เช่น โซนห้องแอร์, โซนสวน, ชั้น 2)
  2.2 restaurant_tables      - ข้อมูลโต๊ะอาหารและ QR Code Token

กลุ่มที่ 3: ระบบจัดการเมนูอาหาร (Menus & Categories)
  3.1 categories             - หมวดหมู่อาหาร/เครื่องดื่ม
  3.2 menus                  - รายการเมนูอาหาร
  3.3 option_groups          - กลุ่มตัวเลือกเสริม (เช่น ระดับความเผ็ด, ขนาดแก้ว, ท็อปปิ้ง)
  3.4 option_items           - รายการตัวเลือกย่อยในแต่ละกลุ่ม (เช่น เผ็ดน้อย, เพิ่มไข่ดาว +10)
  3.5 menu_option_groups     - ตารางเชื่อมระหว่างเมนูกับกลุ่มตัวเลือก

กลุ่มที่ 4: ระบบการสั่งอาหารและออเดอร์ (Orders & Order Items)
  4.1 orders                 - บิลการสั่งอาหารหลักของแต่ละโต๊ะ
  4.2 order_items            - รายการอาหารแต่ละจานในบิล
  4.3 order_item_options     - ตัวเลือกเสริมที่ลูกค้าเลือกสำหรับอาหารจานนั้นๆ

กลุ่มที่ 5: ระบบการเงินและการแจ้งเตือน (Payments & Service Calls)
  5.1 payments               - บันทึกการชำระเงินและหลักฐานการจ่าย
  5.2 service_calls          - การแจ้งเตือนเรียกพนักงานจากโต๊ะอาหาร

1.1 ตาราง `users` (ผู้ใช้งานระบบ)
--------------------------------------------------------------------------------
เก็บข้อมูลผู้ใช้งานระบบทุกระดับ (Super Admin, Store Manager, Store Staff)

| Column Name     | Data Type     | Constraints / Default        | Description                               |
|-----------------|---------------|------------------------------|-------------------------------------------|
| id              | BIGINT (PK)   | AUTO_INCREMENT / SERIAL      | รหัสประจำตัวผู้ใช้                        |
| username        | VARCHAR(50)   | UNIQUE, NOT NULL             | ชื่อผู้ใช้สำหรับล็อกอิน                   |
| email           | VARCHAR(100)  | UNIQUE, NOT NULL             | อีเมล                                     |
| password_hash   | VARCHAR(255)  | NOT NULL                     | รหัสผ่านที่ผ่านการ Hash (Bcrypt/Argon2)   |
| full_name       | VARCHAR(100)  | NOT NULL                     | ชื่อ-นามสกุล                              |
| phone_number    | VARCHAR(20)   | NULL                         | เบอร์โทรศัพท์                             |
| role            | ENUM / VARCHAR| NOT NULL ('admin','user')    | บทบาทหลักในระบบ (admin = ดูแลระบบกลาง)   |
| is_active       | BOOLEAN       | DEFAULT TRUE                 | สถานะการเปิดใช้งาน (TRUE=ใช้งาน, FALSE=ระงับ)|
| created_at      | TIMESTAMP     | DEFAULT CURRENT_TIMESTAMP    | วันเวลาที่สร้าง                           |
| updated_at      | TIMESTAMP     | ON UPDATE CURRENT_TIMESTAMP  | วันเวลาที่แก้ไขล่าสุด                     |

| is_open         | BOOLEAN       | DEFAULT TRUE                 | สถานะเปิด/ปิดรับออเดอร์ของร้าน            |

| updated_at      | TIMESTAMP     | ON UPDATE CURRENT_TIMESTAMP  | วันเวลาที่แก้ไขล่าสุด                     |

| UNIQUE KEY      | (store_id, user_id)                          | 1 บัญชีผู้ใช้มี 1 บทบาทต่อ 1 ร้าน         |

2.2 ตาราง `restaurant_tables` (ข้อมูลโต๊ะอาหาร)
--------------------------------------------------------------------------------
เก็บข้อมูลโต๊ะ สถานะโต๊ะ และ Token สำหรับสร้าง QR Code ให้ลูกค้าสแกน

| Column Name     | Data Type     | Constraints / Default        | Description                               |
|-----------------|---------------|------------------------------|-------------------------------------------|
| id              | BIGINT (PK)   | AUTO_INCREMENT / SERIAL      | รหัสประจำโต๊ะ                             |
| store_id        | BIGINT (FK)   | NOT NULL -> stores(id)       | รหัสร้านค้า                               |

| table_number    | VARCHAR(20)   | NOT NULL                     | หมายเลขหรือชื่อโต๊ะ (เช่น T-01, VIP-1)    |
| seat_capacity   | INT           | DEFAULT 4                    | จำนวนที่นั่งรองรับ                        |
| qr_token        | VARCHAR(100)  | UNIQUE, NOT NULL             | รหัส Token สุ่มเฉพาะโต๊ะสำหรับสร้าง QR Code |
| status          | ENUM / VARCHAR| DEFAULT 'available'          | สถานะโต๊ะ:                                |
|                 |               |                              | - 'available'   = ว่าง                    |
|                 |               |                              | - 'occupied'    = มีลูกค้านั่ง/กำลังทาน   |
|                 |               |                              | - 'reserved'    = จองแล้ว                  |
|                 |               |                              | - 'cleaning'    = รอทำความสะอาด/เคลียร์โต๊ะ|
| current_order_id| BIGINT (FK)   | NULL                         | รหัสออเดอร์ปัจจุบันที่กำลังเปิดใช้งานอยู่ |
| is_active       | BOOLEAN       | DEFAULT TRUE                 | เปิดใช้งานโต๊ะนี้หรือไม่                  |
| created_at      | TIMESTAMP     | DEFAULT CURRENT_TIMESTAMP    | วันเวลาที่สร้าง                           |
| updated_at      | TIMESTAMP     | ON UPDATE CURRENT_TIMESTAMP  | วันเวลาที่แก้ไขล่าสุด                     |
| UNIQUE KEY      | (store_id, table_number)                     | หมายเลขโต๊ะต้องไม่ซ้ำกันในร้านเดียวกัน    |

5. ดัชนีการค้นหาเพื่อประสิทธิภาพ (Recommended Database Indexes)
================================================================================
1. `CREATE INDEX idx_tables_store_token ON restaurant_tables(store_id, qr_token);`
   - เพื่อให้ค้นหาโต๊ะจาก QR Code ได้รวดเร็วที่สุดระดับเสี้ยววินาที
2. `CREATE INDEX idx_menus_store_category ON menus(store_id, category_id, is_available);`
   - เพื่อให้การโหลดเมนูหน้าร้านของลูกค้าลื่นไหล
3. `CREATE INDEX idx_orders_store_status ON orders(store_id, status, created_at);`
   - เพื่อให้ Dashboard และหน้าแสดงผลของร้านค้าดึงข้อมูลได้อย่างรวดเร็ว
4. `CREATE INDEX idx_order_items_order_status ON order_items(order_id, status);`
   - เพื่อให้ระบบหน้าจอครัว (KDS) ดึงรายการอาหารที่กำลังทำได้ทันที
