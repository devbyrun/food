1. ภาพรวมสถาปัตยกรรมระบบ (System Architecture Overview)
--------------------------------------------------------------------------------
ระบบถูกออกแบบเป็นเว็บแอปพลิเคชันที่รองรับการใช้งานผ่าน Responsive Web Design
(ทั้งมือถือ แท็บเล็ต และคอมพิวเตอร์) โดยแบ่งพื้นที่การทำงานหลักออกเป็น 3 ส่วน:

1. Customer Portal (หน้าร้านค้าสำหรับลูกค้า): 
   - ใช้งานผ่านสมาร์ตโฟนด้วยการสแกน QR Code ประจำโต๊ะ
   - ไม่ต้องดาวน์โหลดแอปพลิเคชัน และไม่ต้องล็อกอิน
   - สั่งอาหาร ติดตามสถานะ และเรียกพนักงานได้แบบ Realtime

2. Store Portal (ระบบจัดการร้านค้า - ผู้จัดการ & พนักงาน):
   - รองรับการใช้งานผ่าน Tablet / Desktop / POS
   - ระบบมอนิเตอร์สถานะโต๊ะสด (Live Table Map)
   - หน้าจอรับออเดอร์สำหรับห้องครัว (Kitchen Display System - KDS)
   - ระบบจัดการเมนูอาหาร โต๊ะ และการเงิน/แคชเชียร์

3. Platform Admin Portal (ระบบผู้ดูแลระบบหลัก):
   - สำหรับผู้ดูแลระบบทั้งหมด (Super Admin) จัดการร้านค้า สถิติภาพรวม และความปลอดภัย

ส่วนที่ 1: ส่วนกลางและระบบยืนยันตัวตน (Public & Authentication)
--------------------------------------------------------------------------------
- `/`                               -> หน้า Landing Page แนะนำระบบ / ลิงก์เข้าสู่ระบบ
- `/login`                          -> หน้าเข้าสู่ระบบ (ระบบจะตรวจสอบ Role และ Redirect ไปยังหน้าเหมาะสมอัตโนมัติ)
- `/forgot-password`                -> หน้ารีเซ็ตรหัสผ่าน
- `/unauthorized`                   -> หน้าแจ้งเตือนไม่มีสิทธิ์เข้าถึง (403)
- `/404`                            -> หน้า Page Not Found


--------------------------------------------------------------------------------
ส่วนที่ 2: หน้าร้านค้าสำหรับลูกค้า (Customer QR Ordering)
เข้าถึงผ่านการสแกน QR Code ประจำโต๊ะ
--------------------------------------------------------------------------------
URL รูปแบบ: `/order/:store_slug/:qr_token`

- `/order/:store_slug/:qr_token`
  ├─ [1. Header]: แสดงชื่อร้าน, หมายเลขโต๊ะ (เช่น "โต๊ะ T-05"), สถานะร้าน
  ├─ [2. Promotion/Banner]: แบนเนอร์โปรโมชัน หรือเมนูแนะนำพิเศษ
  ├─ [3. Category Bar]: แถบเลื่อนหมวดหมู่อาหาร (ทั้งหมด, จานด่วน, ของทานเล่น, เครื่องดื่ม)
  ├─ [4. Menu Grid/List]: การ์ดแสดงรายการอาหาร (รูปภาพ, ชื่อ, รายละเอียด, ราคา, ปุ่มกดสั่ง)
  ├─ [5. Menu Detail Modal]: หน้าต่างป๊อปอัปเลือกตัวเลือกเสริม (เช่น ระดับความเผ็ด, เพิ่มไข่ดาว) และระบุหมายเหตุ
  ├─ [6. Floating Cart Bar]: แถบตะกร้าลอยด้านล่าง แสดงจำนวนจานและยอดรวมแบบ Realtime
  │
- `/order/:store_slug/:qr_token/cart`
  ├─ สรุปรายการอาหารที่เลือกในตะกร้า
  ├─ ปรับเพิ่ม/ลดจำนวน หรือลบรายการ
  ├─ ระบุชื่อลูกค้า/จำนวนคน (Optional)
  └─ ปุ่ม "ยืนยันการสั่งอาหาร (Send Order to Kitchen)"
  │
- `/order/:store_slug/:qr_token/status`
  ├─ หน้ารายการอาหารที่สั่งไปแล้วของโต๊ะนี้ (Live Order Tracking)
  ├─ แสดงสถานะแยกรายจาน: [รอดำเนินการ 🕒] -> [กำลังปรุง 👨‍🍳] -> [เสิร์ฟแล้ว 🍽️]
  ├─ สรุปยอดรวมค่าอาหารทั้งหมดปัจจุบัน
  ├─ ปุ่ม "สั่งอาหารเพิ่ม"
  └─ ปุ่ม "เรียกพนักงาน (Call Staff)" / "ขอเช็คบิล (Request Bill)"

ส่วนที่ 3: ระบบจัดการร้านค้า (Store Management Portal - Manager & Staff)
เข้าถึงเฉพาะผู้ใช้ที่มีสิทธิ์สังกัดร้านค้านั้นๆ
--------------------------------------------------------------------------------
URL รูปแบบ: `/store-admin/...` หรือ `/dashboard/...`

- `/store-admin/dashboard` (ภาพรวมร้านค้า)
  ├─ แสดงสถิติด่วน: ยอดขายวันนี้, จำนวนโต๊ะที่กำลังใช้งาน, จำนวนออเดอร์ที่กำลังปรุง
  └─ กราฟแสดงช่วงเวลาที่มีลูกค้าหนาแน่น (Peak Hours)

- `/store-admin/tables` (ระบบจัดการโต๊ะอาหาร - Live Table Monitoring)
  ├─ แสดงแผนผังโต๊ะหรือการ์ดโต๊ะทั้งหมด แยกตามโซน
  ├─ แสดงสถานะสดของแต่ละโต๊ะ:
  │   - สีเขียว = โต๊ะว่าง (Available)
  │   - สีแดง/ส้ม = มีลูกค้านั่ง (Occupied) + แสดงเวลาที่นั่ง และยอดรวม
  │   - สีฟ้า = กำลังรออาหาร
  │   - สีม่วง = ลูกค้าขอเช็คบิล
  │   - สีเทา = รอทำความสะอาด/เคลียร์โต๊ะ
  ├─ เมนูจัดการโต๊ะ: เพิ่มโต๊ะ, แก้ไขชื่อโต๊ะ/จำนวนที่นั่ง, ลบโต๊ะ
  └─ ปุ่ม "สร้าง QR Code" / "พิมพ์ QR Code ทั้งหมด" (Print Table QR Sheet)

- `/store-admin/menus` (ระบบจัดการเมนูอาหาร)
  ├─ หน้าแสดงรายการเมนูทั้งหมด แบ่งตามหมวดหมู่
  ├─ สวิตช์เปิด/ปิด "สถานะพร้อมขาย/ของหมด" (Quick Toggle Out of Stock)
  ├─ ฟอร์ม เพิ่ม/แก้ไข เมนูอาหาร:
  │   - ชื่อเมนู, หมวดหมู่, ราคาปกติ, ราคาโปรโมชัน
  │   - อัปโหลดรูปภาพอาหาร
  │   - ผูกกลุ่มตัวเลือกเสริม (Option Groups)
  ├─ จัดการหมวดหมู่ (Categories): เพิ่ม/ลบ/แก้ไข/จัดลำดับ
  └─ จัดการกลุ่มตัวเลือกเสริม (Option Groups & Items): เช่น ระดับความหวาน, ท็อปปิ้ง

- `/store-admin/kitchen` (ระบบหน้าจอครัว - Kitchen Display System: KDS)
  ├─ หน้าจอ Realtime แสดงรายการอาหารที่ลูกค้ากดสั่งเข้ามาทันที (มีเสียงแจ้งเตือน)
  ├─ การ์ดออเดอร์แยกตามโต๊ะและเวลาที่สั่ง (นับเวลา Timer)
  ├─ ปุ่มเปลี่ยนสถานะการทำอาหาร: [กดรับออเดอร์] -> [ปรุงเสร็จ] -> [เสิร์ฟแล้ว]
  └─ ตัวกรองตามสถานะหรือแยกตามแผนก (ครัวร้อน / บาร์เครื่องดื่ม)

- `/store-admin/pos` (ระบบแคชเชียร์ & เช็คบิล - Cashier / POS)
  ├─ ดูยอดเงินรวมของโต๊ะที่เรียกเช็คบิล
  ├─ คำนวณส่วนลด, ภาษี (VAT), และ Service Charge
  ├─ เลือกวิธีชำระเงิน (เงินสด / สร้าง Dynamic QR Code PromptPay / บัตร)
  ├─ บันทึกการรับเงิน และพิมพ์ใบเสร็จรับเงิน
  └─ ปุ่ม "ปิดบิลและเคลียร์สถานะโต๊ะให้เป็นโต๊ะว่าง"

- `/store-admin/reports` (รายงานยอดขาย - สิทธิ์เฉพาะผู้จัดการ)
  ├─ รายงานสรุปยอดขาย (รายวัน / รายสัปดาห์ / รายเดือน / เลือกช่วงเวลาได้)
  ├─ รายงานจัดอันดับเมนูขายดี (Top Selling Items)
  ├─ รายงานประเภทการชำระเงิน (สัดส่วนเงินสด vs สแกนโอน)
  └─ ส่งออกข้อมูลเป็นไฟล์ Excel / CSV / PDF

- `/store-admin/staffs` (จัดการพนักงาน - สิทธิ์เฉพาะผู้จัดการ)
  ├─ รายชื่อพนักงานในร้าน
  ├─ เพิ่มพนักงานใหม่ (กำหนด Username, Password, บทบาท: Manager/Staff)
  ├─ แก้ไขข้อมูล และระงับ/ลบบัญชีพนักงาน

- `/store-admin/settings` (ตั้งค่าร้านค้า - สิทธิ์เฉพาะผู้จัดการ)
  ├─ ข้อมูลร้าน: ชื่อร้าน, ที่อยู่, เบอร์โทร, รูปโลโก้, รูปแบนเนอร์
  ├─ ตั้งค่าการเงิน: เลขพร้อมเพย์รับเงิน, อัตรา VAT (%), Service Charge (%)
  ├─ ตั้งค่า Telegram Integration:
  │   - Bot Token: ใส่ Telegram Bot Token
  │   - Kitchen Group Chat ID: ID กลุ่มทีมครัว
  │   - Service Group Chat ID: ID กลุ่มทีมเสิร์ฟ
  │   - ปุ่ม "ทดสอบส่งข้อความแจ้งเตือน (Test Notification)"
  └─ สวิตช์ เปิด/ปิด รับออเดอร์ของร้านค้า

ส่วนที่ 4: ระบบผู้ดูแลระบบส่วนกลาง (Platform Admin Portal - Super Admin)
--------------------------------------------------------------------------------
URL รูปแบบ: `/platform-admin/...`

- `/platform-admin/dashboard`       -> ภาพรวมทั้งระบบ (จำนวนร้านค้าทั้งหมด, ปริมาณการใช้งาน, ยอดทรานแซกชัน)

- `/platform-admin/users`           -> จัดการผู้ใช้ทั้งหมดในระบบ (สร้างบัญชีเจ้าของร้าน/แอดมิน)
- `/platform-admin/system-logs`     -> ตรวจสอบประวัติการทำงานและความปลอดภัยของระบบ

ส่วนที่ 5: ระบบเชื่อมต่อเบื้องหลัง (API & Telegram Webhook Endpoints)
--------------------------------------------------------------------------------
- `POST /api/orders/create`                 -> บันทึกออเดอร์จากลูกค้า + ส่งข้อความเข้ากลุ่ม Telegram ครัว
- `POST /api/telegram/webhook`              -> รับ Callback Query เมื่อกดปุ่มบน Telegram:
  ├─ Action: `kitchen_done`   -> เปลี่ยนสถานะเป็น Ready + ส่งแจ้งเตือนเข้ากลุ่ม Telegram เสิร์ฟ
  └─ Action: `service_served` -> เปลี่ยนสถานะเป็น Served + อัปเดตสถานะในระบบ
- `GET/POST /api/tables/...`                -> จัดการโต๊ะและ Token
- `GET/POST /api/menus/...`                 -> จัดการเมนูและตัวเลือกอาหาร

4. ลำดับขั้นตอนการทำงานของระบบ (System Workflows)
================================================================================

--------------------------------------------------------------------------------
Flow 1: ขั้นตอนการสั่งอาหารของลูกค้า (Customer Journey)
--------------------------------------------------------------------------------
1. ลูกค้านั่งที่โต๊ะ -> เปิดกล้องมือถือสแกน QR Code ที่ติดอยู่บนโต๊ะ
2. ระบบเปิดเว็บเบราว์เซอร์ไปที่ `/order/:store_slug/:qr_token` โดยอัตโนมัติ
3. ระบบตรวจสอบความถูกต้องของ Token และแสดงเมนูอาหารของร้านค้านั้น
4. ลูกค้าเลือกเมนูอาหาร -> เลือก Option เสริม -> ระบุหมายเหตุ -> ใส่ตะกร้า
5. ลูกค้าเปิดหน้าตะกร้า -> ตรวจสอบรายการ -> กดยืนยันการสั่งอาหาร
6. ระบบบันทึก Order ลงฐานข้อมูล และส่งข้อมูลแบบอัตโนมัติ:
   - ส่งข้อความแจ้งเตือนเข้ากลุ่ม **Telegram ทีมครัว** (พร้อมปุ่ม "ปรุงเสร็จแล้ว")
   - ส่งสัญญาณ Realtime ไปยังหน้าจอครัว (KDS) และหน้าจอจัดการโต๊ะของพนักงาน
7. หน้าจอของลูกค้าเปลี่ยนเป็นหน้าติดตามสถานะอาหาร (Live Order Tracking) แบบเรียลไทม์
8. เมื่อทานเสร็จ ลูกค้าสามารถกดปุ่ม "เรียกเช็คบิล" เพื่อแจ้งเตือนไปยังพนักงาน

--------------------------------------------------------------------------------
Flow 2: ขั้นตอนการจัดการร้านค้าและ Telegram Flow (Store & Telegram Operations Flow)
--------------------------------------------------------------------------------
1. ลูกค้าเดินเข้าร้าน -> พนักงานดูสถานะโต๊ะจากหน้า `/store-admin/tables` แล้วพาไปนั่งโต๊ะที่ "ว่าง"
2. เมื่อลูกค้าสั่งอาหาร -> กลุ่ม Telegram ทีมครัว และหน้าจอ KDS ได้รับแจ้งเตือนรายการอาหารใหม่
3. พ่อครัวปรุงอาหารเสร็จ -> กดปุ่ม "ยืนยันปรุงเสร็จแล้ว" ผ่าน Telegram (หรือจอบนเว็บ)
4. ระบบส่งข้อความแจ้งเตือนอัตโนมัติเข้ากลุ่ม **Telegram ทีมเสิร์ฟ** (ระบุโต๊ะและรายการอาหาร)
5. พนักงานนำอาหารไปเสิร์ฟ -> กดปุ่ม "เสิร์ฟเรียบร้อย" บน Telegram
6. ลูกค้าแจ้งเช็คบิล -> หน้าจอแคชเชียร์ `/store-admin/pos` แสดงยอดเงินรวมของโต๊ะนั้น
7. ลูกค้าชำระเงิน (สแกน QR หรือเงินสด) -> พนักงานกดยืนยันการชำระเงิน
8. ระบบบันทึกการชำระเงิน -> ปิดบิล -> ปรับสถานะโต๊ะกลับเป็น "ว่าง (Available)" พร้อมรับลูกค้ารายต่อไป

5. เทคโนโลยีและส่วนประกอบที่แนะนำ (Recommended Tech Stack & Libraries)
================================================================================
- Frontend (Client & Admin UI):
  * Next.js / React หรือ Vite + React (รองรับ SSR/SPA ประสิทธิภาพสูง)
  * CSS Framework: TailwindCSS หรือ Modern CSS (Flexbox/Grid, CSS Variables)
  * State Management: Zustand หรือ React Context สำหรับจัดการตะกร้าสินค้า
  * Realtime Client: Socket.io-client หรือ Supabase Realtime / Server-Sent Events (SSE)
  * QR Code Generator: `qrcode.react` หรือ `canvas-confetti` สำหรับลูกเล่น UI

- Backend (API Server):
  * Node.js (Express / NestJS) หรือ Next.js API Routes / Go
  * Realtime Protocol: WebSockets (Socket.io) สำหรับส่งออเดอร์และแจ้งเตือนสด
  * ORM / Query Builder: Prisma / Drizzle ORM / TypeORM

- Database:
  * PostgreSQL หรือ MySQL 8.0+
  * Caching & Session: Redis (สำหรับเก็บแคชสถานะโต๊ะสดและ Socket Session)
================================================================================
