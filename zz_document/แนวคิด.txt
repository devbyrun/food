================================================================================
                      แนวคิดระบบสั่งอาหารตามโต๊ะผ่าน QR Code
            (Table QR Code Food Ordering System with Telegram Workflow)
================================================================================

1. ภาพรวมระบบ (System Overview)
--------------------------------------------------------------------------------
ระบบเว็บแอปพลิเคชันสำหรับสั่งอาหารตามโต๊ะอาหารแบบ Multi-Store (รองรับหลายร้านค้า)
โดยแต่ละร้านค้าจะมีพื้นที่หน้าร้านและระบบจัดการหลังบ้านเป็นของตนเอง ลูกค้าสามารถ
นั่งที่โต๊ะแล้วใช้สมาร์ตโฟนสแกน QR Code ประจำโต๊ะเพื่อดูเมนู สั่งอาหาร และติดตาม
สถานะได้ทันที พร้อมระบบแจ้งเตือนและประสานงานผ่าน Telegram Bot สำหรับทีมครัวและทีมเสิร์ฟ


--------------------------------------------------------------------------------
2. บทบาทและสิทธิ์ผู้ใช้งาน (Roles & Permissions)
--------------------------------------------------------------------------------
1. ผู้ดูแลระบบกลาง (Super Admin / Admin):
   - ดูแลและจัดการภาพรวมของระบบทั้งหมด
   - จัดการร้านค้า (เพิ่ม, ระงับ, แก้ไขร้านค้าในระบบ)
   - จัดการบัญชีผู้จัดการร้านค้า

2. ผู้จัดการร้านค้า (Store Manager):
   - จัดการข้อมูลร้านค้า (เวลาเปิด-ปิด, บัญชีรับเงิน, ภาษี/ค่าบริการ)
   - จัดการโต๊ะอาหาร (เพิ่ม, ลบ, แก้ไข, สร้าง/พิมพ์ QR Code ประจำโต๊ะ)
   - จัดการเมนูอาหารและหมวดหมู่ (เพิ่ม, ลบ, แก้ไข, อัปเดตรูป, เปิด/ปิดสถานะของหมด)
   - จัดการผู้ใช้งานในร้าน (เพิ่ม, แก้ไข, ลบบัญชีพนักงาน)
   - ดูรายงานยอดขาย สถิติ และรายงานการดำเนินงาน
   - จัดการตั้งค่า Telegram Bot สำหรับทีมครัวและทีมเสิร์ฟ

3. พนักงานร้านค้า (Store Staff):
   - จัดการโต๊ะอาหาร (ดูสถานะโต๊ะ ว่าง/ไม่ว่าง, สลับโต๊ะ, เคลียร์โต๊ะ)
   - จัดการเมนูอาหาร (เพิ่ม, ลบ, แก้ไขเมนู, เปิด/ปิดสถานะเมนูหมด)
   - รับออเดอร์หน้าร้าน บริการลูกค้า และคิดเงิน/เช็คบิล

4. ลูกค้า (Customer):
   - สแกน QR Code ประจำโต๊ะเพื่อเข้าหน้าร้านค้าของโต๊ะนั้นๆ (ไม่ต้องล็อกอิน)
   - ดูรายการอาหาร ค้นหาเมนู และดูรายละเอียด
   - เลือกตัวเลือกพิเศษ (เช่น ระดับความเผ็ด, ท็อปปิ้ง) และระบุหมายเหตุ
   - กดยืนยันสั่งอาหาร และติดตามสถานะอาหารแบบเรียลไทม์
   - กดเรียกพนักงาน หรือขอเช็คบิล


--------------------------------------------------------------------------------
3. ส่วนประกอบหลักของระบบ (Core Modules)
--------------------------------------------------------------------------------
3.1 หน้าหลักและระบบเข้าสู่ระบบ (Home & Authentication):
    - หน้า Landing Page แนะนำระบบ และฟอร์มล็อกอินเข้าสู่ระบบ
    - ตรวจสอบสิทธิ์ผู้ใช้และนำทางไปยังแดชบอร์ดตาม Role อัตโนมัติ

3.2 ระบบหน้าร้านค้าสำหรับลูกค้า (Customer QR Ordering):
    - หน้าร้านค้าเฉพาะของแต่ละร้าน (รองรับ Multi-store)
    - ระบบระบุโต๊ะอัตโนมัติผ่าน QR Code
    - แสดงเมนูอาหารแยกตามหมวดหมู่ พร้อมรูปภาพและราคา
    - ตะกร้าสินค้า และหน้าติดตามสถานะอาหาร (Live Order Tracking)

3.3 ระบบจัดการร้านค้า (Store Management Portal):
    - ระบบมอนิเตอร์สถานะโต๊ะสด (ว่าง / ไม่ว่าง / รออาหาร / รอเช็คบิล)
    - ระบบจัดการเมนู หมวดหมู่ และตัวเลือกเสริม
    - ระบบรับออเดอร์หน้าร้าน และระบบแคชเชียร์ (POS / Billing)
    - ระบบรายงานยอดขาย และจัดการผู้ใช้ในร้าน (เฉพาะผู้จัดการ)


--------------------------------------------------------------------------------
4. ขั้นตอนการทำงานและการแจ้งเตือนผ่าน Telegram (Telegram Workflow)
--------------------------------------------------------------------------------
[ ขั้นตอนที่ 1: ลูกค้าสั่งอาหาร ]
   ลูกค้านั่งที่โต๊ะ -> สแกน QR Code -> เลือกเมนู -> กดยืนยันการสั่งอาหาร
   └──> 1. บันทึกข้อมูลออเดอร์ลงฐานข้อมูล
   └──> 2. ส่งข้อความแจ้งเตือนอัตโนมัติเข้ากลุ่ม "Telegram ทีมครัว" 👨‍🍳
        (รายละเอียด: โต๊ะ, รายการอาหาร, จำนวน, หมายเหตุ, ปุ่ม Inline "กดทำเสร็จแล้ว")

[ ขั้นตอนที่ 2: ทีมครัวปรุงอาหารเสร็จ ]
   เมื่อพ่อครัวทำอาหารเสร็จ -> กดปุ่ม "ยืนยันทำเสร็จแล้ว (Done)" บนข้อความ Telegram นั้น
   └──> 1. ระบบอัปเดตสถานะอาหารในฐานข้อมูลเป็น "พร้อมเสิร์ฟ (Ready)"
   └──> 2. ข้อความในกลุ่มครัวอัปเดตสถานะว่าปรุงเสร็จแล้ว
   └──> 3. ส่งข้อความแจ้งเตือนอัตโนมัติเข้ากลุ่ม "Telegram ทีมเสิร์ฟ" 🍽️
        (รายละเอียด: โต๊ะที่ต้องเสิร์ฟ, รายการอาหาร, ปุ่ม Inline "เสิร์ฟเรียบร้อย")

[ ขั้นตอนที่ 3: เสิร์ฟอาหารและเช็คบิล ]
   พนักงานนำอาหารไปเสิร์ฟที่โต๊ะ -> กดปุ่ม "เสิร์ฟเรียบร้อย" บน Telegram หรือบนเว็บ
   └──> 1. ระบบอัปเดตสถานะอาหารเป็น "เสิร์ฟแล้ว (Served)"
   └──> 2. เมื่อลูกค้าทานเสร็จ -> แจ้งเช็คบิล -> รับชำระเงิน -> ปรับสถานะโต๊ะกลับเป็น "ว่าง (Available)"
